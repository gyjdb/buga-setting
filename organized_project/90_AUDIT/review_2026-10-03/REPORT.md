# 项目审核：非创作维护与必要订正（最终版）

本版按作者最新意见调整重点：文学方面继续由 Claude 审核，本轮主要审视非创作部分的过度防御、检查负担和维护重复。配套：[维护与后续草拟顺序](DRAFTING_ORDER.md)、[给 Claude 的执行 prompt](CLAUDE_PROMPT.md)。此前详细证据保留在根仓库提交 `ab9fc00` 中。

## 一、总体判断

现有项目真正需要近期处理的是转述条件漏失、资料同步不完整，以及网站把历史审计当作当前状态展示。它们有明确依据，可以集中修正。

非创作方面的减负，重点应放在 agent 的执行尺度：不要把局部补白当成全局故障，不要反复确认已有授权，不要为普通修正新增多套台账、快照和校验要求。现有 Git、Canon 清单与门户构建检查各有作用，并非都应删减。

上一版将文学规则松绑和第五章重写列得过于突出，本版移出本轮执行重点。风土志篇章、修辞和文学校订由 Claude 按原有安排判断；涉及法条条件的事实转述仍可订正。

## 四、非创作部分怎样减负

### 1. 检查随改动选择，一轮完成后统一运行

[门户 README](../../../tools/library_portal/README.md)L50–55 的常规流程是重建和 `verify.py`；风土志正文变化时才加书页计划检查。L192 是机构的针对性检查，L198–199 明确全文搜索测试可选，没有要求每次普通文档改动都跑全部测试。

合理执行方式是一轮改完后统一构建、校验，按受影响功能补必要检查。后续没有新修改、失败或具体疑问，就不重复跑同一批检查，也不自动扩展到全部浏览器、版式和搜索测试。

### 2. 保留有用途的自动校验，减少额外重复工作

[verify.py](../../../tools/library_portal/verify.py)L46–56 检查源文件、正式清单与站点副本是否一致，L73–74 检查搜索全文有没有截断，L116 也明说不判断 Canon 内容正确性。这些检查用于防止同步遗漏与错版，可以继续使用。

额外手动计算同一批哈希、反复制作内容保全清单、无改动地多次验证，没有相同收益。交付应说明改了什么和是否通过相关检查，不以检查次数充当质量结论。

### 3. 普通维护采用现有版本与文书

根目录 [AGENTS.md](../../../AGENTS.md)与门户 README 已要求用 Git 提交，并禁止手工复制备份、生成额外内容哈希清单；备份走 `backup.cmd`。本轮不建议再增加新的快照或备份制度。

名称、简介、参考与页面标签等普通修正，通常由文件差异和提交说明记录即可。正式法典升级才按项目规则保留版本与逐条变更说明。不要让每次小改动都附一份新审计报告、场景矩阵、停止点清单和批准账；既有历史材料也不因这次减负而批量删除。

### 4. 已有授权内直接推进，重要设计集中讨论

按已确定的作者答复同步资料，或纠正派生文本的误引，无须逐项重新请求批准。首次试炼、上诉执行等需要补明规范的地方，形成简短建议；真正存在制度分歧的少数问题集中交作者选择。

[OPEN_ISSUES](../../00_PROJECT/OPEN_ISSUES.md)L87–98 对未成文实体法的限制，是提醒不能把未批准方案伪称现行规则。它不应被扩大为禁止在 PROPOSAL 中提出具体制度，也不应让其他维护等待所有未决事项解决。

### 5. 分清世界内安全程序与项目管理要求

[禁魔规程](../../01_CURRENT_CANON/魔法体系与魔法法/禁魔分区规程_v1_3_4.md)附件一 L197–201 对具体设备、条件和绝对禁制区作核验，同时提供物理隔离、场外执行、人工记录等替代办法；附件二 L205 还明确不重复发同一接入许可。不能只因出现“核验”“不得”就判这些条款都过度防御。

应避免的是把世界内程序变成作者设计前必须制作的全部文书，或把一个局部未知扩成国家整体不能运行。制度与设备工作方式可以先作为方案提出，核心魔法未决另行说明。安全约束保留在适当范围，常规运行与解决问题的能力也要体现。

## 五、给下一轮执行的范围

先集中完成资料同步、门户当前与历史状态区分，以及明确的转述勘误。文学审核继续由 Claude 处理，本轮不要求重写第五章，不要求撤除或重构文学技能规则；技能参考中已过时的事实则应更新。

常规检查放在修改完成后进行。只因本轮维护而额外启动全库重审、建立新校验框架或重做全部法规，都没有必要。

后续主题稿继续参考[草拟清单](DRAFTING_ORDER.md)，作为发展路线；本次维护不自动启动全部新模块。执行范围、相关检查及交付方式已整理为[可直接复制的 prompt](CLAUDE_PROMPT.md)。
